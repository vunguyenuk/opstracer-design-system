SYSTEM

OpsTracer design system

Two bands, one signal quartet, one amber action.

DS-01 documents the language the OpsTracer landing page ships today. The page runs a warm paper shell for editorial bands and the SRE Lead dark palette for the nav, the hero and every product panel. Colour speaks four times — amber, red, green, blue — and the only action colour is brand amber.

These values are the resolved output of opstracer-landing-page/index.html, read after all 22 override layers. The base token block at the top of that file is superseded — layer 6 replaces the surfaces, layer 8 flips nav and hero, layer 17 makes every primary action amber. Reading only the top of the file gives the wrong system.

BANDS

Paper for the argument. Dark for the product.

This is not a light/dark theme pair — both bands are on screen at once. The page opens dark (nav + hero), drops to warm paper for the editorial sections, and returns to dark wherever real product UI is shown. The dark band is a scoped token override on nav,.hero, not a theme flip.

VOICE

System / Voice

Technical, decisive, evidence-led.

The positioning is on-call plus AI root cause analysis, sold demo-led. Copy names the artifact — incident, evidence, deploy, rollback, RCA — and every claim is followed immediately by the product surface that proves it.

Show, then claim

Each argument band is followed by a real panel at real density. The proof is the screenshot, not an illustration.

Audit under pressure

Nothing is a black box: every conclusion links to the event behind it, and the UI shows the link.

One action

"Get a live demo" is the only call in the whole page. No self-serve sign-up, no secondary funnel.

TYPE

Foundations / Typography

Host Grotesk argues. DM Mono reports.

Two self-hosted families, split by meaning. Host Grotesk carries prose, field labels and human-readable states. DM Mono carries navigation, action labels, code and machine-readable facts such as timestamps, IDs, paths, tokens and measurements. Navigation and action labels are uppercase; literal source code keeps its syntax casing.

Which step a heading takes, by where it sits.

The two scales above say what sizes exist. This says which one a given element gets, so an h3 inside a product panel is not accidentally set at marketing scale.

STACK

Foundations / Stack & gap

Six named gaps, no arbitrary margins.

The spacing scale above describes the distance between bands. This names the distance between siblings inside a panel, so a form and a table and a card list all breathe at the same six values instead of at whatever the last person typed.

SHAPE

Foundations / Geometry

Square, with one corner cut.

Radius is zero. The signature is a notch on the bottom-right corner, cut with clip-path. It comes in two sizes because it is applied at two scales — 14px on actions and cards, 18px on product panels, 24px on the very wide integration card.

  0 100%

One curve, two speeds.

Interaction moves at .22s; narrative reveals at .5s. Both on cubic-bezier(.22,1,.36,1). Motion exists to show how raw signal becomes traced evidence — the lower sections are scroll-led for exactly that reason.

ICONS

Foundations / Iconography

One outline family, four optical sizes.

Operational icons are outline only — one stroked Nucleo family, stored locally as SVG source files. No pixel-grid, filled or multicolour glyph enters the system. They render as one-colour masks that inherit currentColor, keeping status meaning in the surrounding label instead of introducing a second visual language.

optical scale14 / 16 / 20 / 24px

Header, side nav, content, pane.

The landing page is a stack of full-bleed bands. The app is not — it is one persistent frame that never reloads, with four regions that each own their scroll. This is the first thing the design system owed the product and did not have.

Two columns for settings and setup.

ACTION

Components / Buttons

Clear actions, amber, cut at the corner.

Button labels use DM Mono in uppercase with .04em tracking, giving every action the same compact technical voice as navigation. Every button is square with the 14px notch. There is no blue primary anywhere in the system — an earlier revision had one and layer 17 removed it.

variants.btn

The lead button is hero-only: 296px minimum, DM Mono 18px uppercase, arrow pinned 28px right, no border.

the full variant setwave 1

Danger is --crit, not amber — the one place the action colour is allowed to change, because closing an incident is not the same gesture as acknowledging one.

inactive, not disabled

A disabled button is unreachable by keyboard and says nothing about why. Prefer .inactive: it stays focusable, keeps its accessible name, and the reason goes next to it — "escalation policy not configured". Keep disabled for the few seconds a form is mid-submit.

the ghost is an outline, not a second fill

Ghost rests on --line with the band's own ink, and on hover both border and label go amber. It never takes a fill, so the amber button stays the only filled object in a band.

ICON

Components / Icon buttons

An icon alone still has to say what it does.

A row of records needs actions that do not repeat their label twenty times. Every icon button carries an aria-label and, once the overlay layer lands, a tooltip carrying the same words — not different ones.

variants.ibtn

Small 26px in table rows, medium 32px beside a title, large 40px only when the button is the single action in a panel.

the notch scales with the object

14px is the cut for anything 40px and taller. At 32px it eats a third of the edge, so the cut steps down to 8px; below 28px the object is square and carries no cut at all. Same rule for inputs, filled chips and menu items — written here because icon buttons are where it first bites.

RULES

Guidelines / Do & Don't

The decisions that keep this coherent.

Do

Repaint the notch outline. Clip-path removes the border along the diagonal — put it back with the gradient iso-line on every outlined element that is cut.

Don't

Leave a cut container with an open corner. A frame whose border stops short reads as a rendering bug, not a shape.

Do

Use amber for the single primary action, and for the one thing currently moving.

Don't

Introduce a second action colour. The blue in the signal quartet marks correlation and links — it is never a button.

Do

Give a scoped dark band its own color:var(--ink), or its headings inherit the paper ink and disappear.

Don't

Flip the whole theme to get a dark section. The bands coexist; only the band's tokens change.

Do

Use uppercase DM Mono for timestamps, IDs, paths, tokens, measurements and technical keys. Preserve original casing only in literal source code.

Don't

Set prose, field labels, service names or human-readable states in uppercase mono. Use DM Mono for navigation and action labels; use Host Grotesk whenever longer language needs sentence case.

Do

Pair every state colour with a word. The chip says "Resolved" as well as being green.

Don't

Rely on a dot alone. A colour with no label fails the moment the reader is colour-blind or the screen is dimmed.

Do

Show real density in proof panels — real service names, real timestamps, real error rates.

Don't

Draw placeholder rows. If the data is not real enough to show, the section is not ready.

SCOPE

Guidelines / Scope

This file is the app. The landing page has its own.

Until 08.09.2026 this document described the landing page, and recorded that tables, form fields, modals and tooltips were deliberately absent. That was true of the page and is not true of the product. The landing material now lives in landing.html; this file describes the web app, onboarding and mobile v1, which need every one of those things.

in this file

Foundations shared by all four surfaces — colour, type, scale, spacing, gap, density, geometry, borders, motion, focus, icons. The app shell. Every product component. Guidelines that apply to a screen someone works in.

in landing.html

Nav switches, the eyebrow and rail marker, the globe overlay cards, proof points, and the eight bands as shipped. It reads its tokens from the same resolved palette and does not restate them.

The component set is being built against Primer product as the reference for coverage — not for its look. 62 components audited; wave 1, the app shell, is in this file. Waves 2 and 3 — forms, the real data table, the overlay layer, empty and loading states — are not here yet, and a screen that needs one should say so rather than invent it.
