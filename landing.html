LANDING

Landing page / Scope

The page as shipped, kept as its own record.

Split out of the design system on 08.09.2026. The system file now describes the product surface; this one keeps the landing page — its four page-only components and the eight bands in production — so neither document has to hedge.

Tokens, type, geometry, motion, focus and iconography are not restated here. They live in index.html and this page inherits them unchanged. If a value disagrees between the two files, the rendered landing page wins — it is still the source of truth for the palette.

Sections in production / Embedded panels

Four bands are delivered as captured markup.

The persona panels — SRE Lead, Platform Engineering, VP Engineering — and the two pillar sections are embedded blocks rather than native markup. They carry their own class names and their own font aliases, which is why the canonical type layer is authored last and marked important.

Do not author new work in the embedded idiom. New sections are written natively against the tokens in this document; the embedded blocks are a delivery mechanism to be replaced, and everything they render is already re-specified in the Components group above.
SCOPE

Guidelines / Not in this system

What the page does not contain.

Recorded because it is easy to assume otherwise. None of the following renders anywhere on the landing page, and none of it has a specification here. If a future surface needs one, it is a new decision — not something to copy from an old file.

absent from the rendered page
<table>form fieldsselect menuscheckboxes togglesdashboardsCRM viewsdata grids sortingpaginationrow selectionmodals tooltipsbreadcrumbslogo stripcarousel stats accordionpricing tabletestimonialsblog cards

Verified by counting the rendered markup: zero <table>, zero field wrappers, zero key/value or log blocks.

The landing page's stylesheet still carries CSS for several of these — form controls, key/value rows, an activity log, a control-plane panel — left over from an earlier revision. It is dead code. Nothing renders it, and it is not part of this system. Delete it rather than building on it.
The closest thing to a table is the evidence rows component: a four-column CSS grid for one incident's evidence, with no sorting, paging or selection. Reach for it when the content is a trace. If a future surface genuinely needs a sortable dataset, that is a new component and it needs its own specification.
